# 01 — SRS: ความต้องการระบบ (Software Requirements Specification)

**ระบบ:** Inthara Smart Water ERP v2 — ระบบบริหารจัดการโรงงานผลิตน้ำดื่ม (ERP + TMS)
**เวอร์ชันเอกสาร:** 1.0 | **สถานะ:** อนุมัติให้พัฒนา
**ที่มา:** วิเคราะห์จากระบบเดิม repo `sunantana/inthara-smart-water` (server.js 42 routes, public/app.js 13 views) + รายงาน performance review ลงวันที่ 2026-11-02

---

## 1. ภาพรวมระบบ

โรงงานผลิตและจัดจำหน่ายน้ำดื่ม 4 ขนาด (ถัง 18.9L, ขวด 350ml / 600ml / 1500ml) มีกระบวนการครบวงจร: ผลิต → ควบคุมคุณภาพ → จัดการสต็อก → รับออเดอร์ → วางแผนเส้นทางรถส่ง → ส่งของ/เก็บเงิน → ปิดบิล/ติดตามหนี้ พร้อมงานสนับสนุน (ซ่อมบำรุงเครื่องจักร, สินทรัพย์, พนักงาน, ค่าใช้จ่าย)

**เป้าหมายของ v2:**
1. คงฟีเจอร์ทั้งหมดของระบบเดิม (ตาราง FR ด้านล่าง) โดยแก้ปัญหาสถาปัตยกรรมเดิม: อ่าน/เขียนไฟล์ JSON ทั้งก้อนทุก request, concurrent write ทำข้อมูลหาย, รหัสผ่าน plain + Excel ใน repo
2. รองรับข้อมูล 10,000+ ออเดอร์/เดือน โดย response API p95 < 100ms
3. แยกสิทธิ์ผู้ใช้ 5 ระดับ + พอร์ทัลลูกค้าแยกอิสระ

## 2. ผู้ใช้และสิทธิ์ (RBAC)

| บทบาท | ขอบเขตการใช้งาน |
|---|---|
| `admin` | ทุกอย่าง + จัดการผู้ใช้ + audit log + ตั้งค่าระบบ |
| `manager` | ดูได้ทุกโมดูล + แก้ไขข้อมูลได้ทุกโมดูล ยกเว้นจัดการผู้ใช้ |
| `staff` (สำนักงาน) | ออเดอร์, ลูกค้า, ปิดบิล, รายงาน (ดูเฉพาะที่เกี่ยวข้อง) |
| `driver` (พนักงานขับรถ) | TMS เส้นทางของตัวเอง, ทำ check-in ส่งของ/เก็บเงิน |
| `customer` | พอร์ทัลลูกค้า: ดูราคา/ยอดค้างชำระ/ประวัติ, สั่งน้ำ, แจ้งปัญหา (เข้าด้วย PIN) |

## 3. ความต้องการเชิงฟังก์ชัน (FR) แยกโมดูล

> ระดับความสำคัญ: **[M]** ต้องมี (Must) / **[S]** ควรมี (Should)

### 3.1 ผู้ใช้ & ความปลอดภัย (AUTH)
- AUTH-1 [M] เข้าสู่ระบบด้วย username + password → ได้ access token (อายุ 15 นาที) + refresh token (7 วัน)
- AUTH-2 [M] ล็อกบัญชีชั่วคราวเมื่อพิมพ์ผิด 5 ครั้ง (15 นาที) + แจ้งเหตุผลในหน้า login
- AUTH-3 [M] เปลี่ยนรหัสผ่านด้วย PIN ยืนยัน (เหมือนฟีเจอร์ reset-password-by-pin เดิม)
- AUTH-4 [M] Admin: เพิ่ม/ลบ/แก้ผู้ใช้, ตั้ง role, ปลดล็อก, reset PIN
- AUTH-5 [M] บันทึก audit log ทุกการเข้าสู่ระบบ (สำเร็จ/ล้มเหลว) และทุก action ที่แก้ไขข้อมูล
- AUTH-6 [S] หน้า dashboard แสดง log 25 รายการล่าสุด + กรองตามผู้ใช้/action
- **ห้าม:** เก็บรหัสผ่านแบบ plain, เก็บผู้ใช้ในไฟล์ Excel, การ sync ผู้ใช้จาก Excel อัตโนมัติ (ลบพฤติกรรมเดิมทั้งหมด)

### 3.2 ทะเบียนลูกค้า (CRM)
- CRM-1 [M] CRUD ลูกค้า: ประเภท (บุคคล/ร้านค้า/หน่วยงาน), ที่อยู่แบบไทย (บ้านที่/หมู่/แขวง/อำเภอ/จังหวัด/รหัสไพ้), โซน, โทรศัพท์, เลขผู้เสียภาษี, สาขา
- CRM-2 [M] ตำแหน่ง lat/lng ต่อลูกค้า (ปักหมุดจากแผนที่ หรือ paste ลิงก์ Google Maps — ต้อง resolve URL เป็นพิกัดได้เหมือนเดิม)
- CRM-3 [M] ราคาต่อหน่วยแยก SKU ต่อลูกค้า โดยเริ่มจาก price tier ที่เลือกแล้วปรับได้
- CRM-4 [M] สถานะถังค้างส่ง (outstanding bottles): ยอดถัง 18.9L ที่ลูกค้าถืออยู่ คำนวณจาก ส่งจริง − คืนจริง
- CRM-5 [M] ค้นหา/กรอง ตามชื่อ/โซน/ประเภท + เรียงหน้า (pagination 50/หน้า)
- CRM-6 [M] Export รายชื่อลูกค้าเป็น Excel
- CRM-7 [S] ประวัติการสั่งซื้อ/ชำระเงินย่อต่อลูกค้า

### 3.3 ราคาและ Price Tier (PRC)
- PRC-1 [M] จัดการ price tier (ชื่อ tier + ราคา 4 SKU) แบบ CRUD
- PRC-2 [M] ออเดอร์**บังคับใช้ราคาจากทะเบียนลูกค้าเสมอ** ห้ามแก้ราคาในหน้าออเดอร์ (กติกาเดิม คงไว้)
- PRC-3 [S] ดูประวัติการเปลี่ยนราคาต่อลูกค้า

### 3.4 ออเดอร์ (ORD)
- ORD-1 [M] สร้าง/แก้ไขออเดอร์: เลือกลูกค้า → ระบุจำนวน 4 SKU → ระบุวันส่ง → ระบบคำนวณยอดรวมจากราคาลูกค้า
- ORD-2 [M] สถานะ: `draft` → `confirmed` → `จัดส่งสำเร็จแล้ว` / `ยกเลิก` — ออเดอร์ที่ส่งสำเร็จแล้ว**ห้ามแก้ไข** (กติกาเดิม คงไว้)
- ORD-3 [M] กันกดส่งซ้ำ: ออเดอร์ใหม่ที่ซ้ำลูกค้า+จำนวน+วันส่ง ภายใน 4 วินาที ให้ ignore
- ORD-4 [M] กรอง/ค้นหา: ตามลูกค้า, โซน, วันที่ส่ง, สถานะ, สถานะชำระเงิน (เหมือน history date filter เดิม)
- ORD-5 [M] Export ออเดอร์ตาม filter เป็น Excel
- ORD-6 [M] เมื่อสร้างออเดอร์ ลูกค้าจะถูกเลือกเข้าเส้นทางวันนั้นอัตโนมัติ (เหมือน selectedForRoute เดิม แต่เก็บเป็น data ไม่ใช่ flag บนลูกค้า)

### 3.5 ส่งของ & Check-in รถ (DLV)
- DLV-1 [M] ฟอร์ม check-in: รับจริงแยก 4 SKU, ถังคืน, โหมดเงิน (สด/เครดิต), เงินที่เก็บได้, หมายเหตุ
- DLV-2 [M] ธุรกรรมเดียว (transaction) ต้องทำครบพร้อมกัน: ปิดออเดอร์เป็น "จัดส่งสำเร็จแล้ว" (ยอดตามของส่งจริง) + **ตัดสต็อกสำเร็จทั้ง 4 SKU** + รับถังคืนเข้าสต็อกถังเปล่า + อัปเดตยอดถังค้างส่งลูกค้า + บันทึกการรับเงิน/หนี้ค้าง — ถ้าขั้นตอนใด fail ต้อง rollback ทั้งหมด
- DLV-3 [M] บันทึก stock movement ทุกครั้ง (ใคร ตัดอะไร เหตุผลอะไร) แทนการแก้ตัวเลขสต็อกตรงๆ
- DLV-4 [S] รองรับ check-in จากมือถือของคนขับ (ฟอร์ม responsive น้ำหนักเบา)

### 3.6 การเงิน & ปิดบิล (FIN)
- FIN-1 [M] ต้นทุนส่วนเกิน (deposit) ต่อลูกค้า: รับเงินมัดจำ/ลดยอด/คืนเงิน — ทุก movement มี ledger
- FIN-2 [M] ตั้งยอดหนี้: ยอดส่งแล้วที่ยังไม่ได้เก็บ (unpaid) คำนวณ = ยอดตามออเดอร์ − เงินที่เก็บได้ − ใช้ deposit
- FIN-3 [M] ปิดยอด (billing settle): เลือกลูกค้า + จ่ายเท่าไร + ใช้ deposit เท่าไร → ระบบแจกแจงไล่ปิดรายการค้างชำระเก่าใหม่ (FIFO) เหมือนฟีเจอร์เดิม
- FIN-4 [M] ใบเสร็จ/สลิป: พิมพ์สลิปเก็บเงิน + สลิปสรุปประวัติค้างชำระ (ฟีเจอร์ history slip เดิม)
- FIN-5 [M] ป้องกันยอดติดลบ (Math.max 0 ทุกการคำนวณ เหมือนเดิม)

### 3.7 TMS เส้นทางรถส่ง (TMS)
- TMS-1 [M] แผนที่ Leaflet (OpenStreetMap) แสดงโรงงาน + ป้ายจอดทุกลูกค้าในวันส่ง
- TMS-2 [M] จัดลำดับป้ายด้วยวิธี nearest-neighbor จากโรงงาน แล้วลากเส้น + คำนวณระยะทาง (Haversine, ถ้า API ไม่พร้อม)
- TMS-3 [M] มุมมอง zone: กรองลูกค้าตามโซน เพื่อจัดเที่ยวต่อรถ
- TMS-4 [M] บันทึกเที่ยว (saved trip): รถ, คนขับ, จำนวนป้าย, ระยะทาง, เวลาโดยประมาณ, น้ำมัน (คำนวณจาก fuelRate × ราคาน้ำมัน), ยอดขายประมาณ — เหมือนข้อมูล savedTrips เดิม
- TMS-5 [M] เลือกคนขับ/รถจากทะเบียน พร้อมจำกัดความจุรถ (maxBottles189L/maxPacks) เทียบกับจำนวนที่เที่ยวจุไหม (แจ้งเตือน)
- TMS-6 [S] ปรับลำดับป้ายด้วยการลาก (drag-and-drop) แล้วคำนวณใหม่

### 3.8 ผลิต & คุณภาพน้ำ (PRD)
- PRD-1 [M] บันทึก lot ผลิตรายกะ: แผน vs ผลจริง (4 SKU), ค่า TDS น้ำดิบ, TDS RO, pH
- PRD-2 [M] ตรวจรับ lot: ถ้าค่า QA ออกเกณฑ์ ให้ flag lot เป็น "ไม่ผ่าน" และห้ามตัดเข้า FG อัตโนมัติ
- PRD-3 [M] เมื่อ lot ผ่าน → เพิ่ม FG เข้าสต็อก พร้อม stock movement + เลข lot อ้างอิงย้อนได้
- PRD-4 [M] สร้างเลข lot อัตโนมัติ (รูปแบบ LOT-YYMMDD-กะ-ลำดับ เหมือน auto lot no เดิม)
- PRD-5 [S] แดชบอร์ดผลผลิตต่อกะ/ต่อวัน เทียบแผน

### 3.9 สต็อก & บรรจุภัณฑ์ (INV)
- INV-1 [M] ทะเบียนสต็อก: FG 4 SKU, ถังเปล่า, วัตถุดิบ/อะไหล่ — มี min stock แจ้งเตือนเมื่อต่ำกว่า
- INV-2 [M] รับเข้า lot บรรจุภัณฑ์: เลข lot, วันซื้อ, SKU, จำนวน, ราคา/unit, ผู้ขาย + **การตัดยอดใช้ไปแบบ FIFO ตาม lot** (คงพฤติกรรม remainingQty เดิม)
- INV-3 [M] ค่าใช้จ่าย lot บรรจุภัณฑ์ผูกกับ asset/สินทรัพย์ที่เกี่ยวข้องได้ (assetLinked เดิม)
- INV-4 [S] ปรับสต็อกด้วยเหตุผล (adjustment) — บันทึกเป็น movement เสมอ

### 3.10 CMMS เครื่องจักร & ซ่อมบำรุง (MNT)
- MNT-1 [M] ทะเบียนเครื่องจักร: รหัส, ชื่อ, หมวด, ยี่ห้อ/รุ่น, กำลัง, สถานะ, ชั่วโมงรัน
- MNT-2 [M] บันทึกงานซ่อม/PM: วันที่, ชนิด (ซ่อม/PM), รายละเอียด, ช่าง, ค่าใช้จ่าย, อะไหล่ที่ใช้ (ตัดจากสต็อกอะไหล่อัตโนมัติ)
- MNT-3 [M] ตั้งเวลา PM ตามชั่วโมงรัน (pmIntervalHours) → แจ้งเตือนเมื่อใกล้ครบ
- MNT-4 [M] แก้สถานะเครื่อง (available/in_use/maintenance) พร้อมผูกกับ asset ที่เกี่ยวข้อง (คง sync เดิมแต่ทำเป็น event ไม่ใช่วนลูปทุก request)

### 3.11 สินทรัพย์ & ค่าเสื่อมราคา (AST)
- AST-1 [M] ทะเบียนสินทรัพย์: หมวด, ยี่ห้อ/รุ่น, SN, ที่ตั้ง, วันซื้อ, ราคา, อายุใช้งาน, มูลค่าซาก
- AST-2 [M] คำนวณค่าเสื่อม (straight-line ต่อปี + สะสม) และมูลค่าคงเหลือ ณ วันที่
- AST-3 [M] พนักงานรับผิดชอบต่อสินทรัพย์ (assignedEmployeeId) + ผูกกับรถ (assetId)
- AST-4 [M] ทะเบียนรถ: ทะเบียน, ยี่ห้อ/รุ่น, ความจุ, fuelRate, สถานะ, คนขับเริ่มต้น — เชื่อม 1:1 กับ asset ประเภทรถ

### 3.12 พนักงาน (EMP)
- EMP-1 [M] ทะเบียนพนักงาน: ข้อมูลส่วนตัว, ตำแหน่ง, แผนก, ประเภทเงินเดือน, วันเริ่มงาน, ใบขับขี่ + วันหมดอายุ (แจ้งเตือนก่อนหมด 30 วัน)
- EMP-2 [M] สถานะ active/inactive; พนักงาน inactive ห้ามถูกเลือกเป็นคนขับ/ผู้รับผิดชอบใหม่
- EMP-3 [M] ผูกพนักงานกับบัญชีผู้ใช้ระบบได้ (username) สำหรับ driver login

### 3.13 ค่าใช้จ่าย & ต้นทุน (EXP)
- EXP-1 [M] บันทึกค่าใช้จ่าย: วันที่, หมวด (น้ำมัน/ซ่อม/สาธารณูปโภค/อื่นๆ), อ้างอิง (รถ/lot/เครื่อง), จำนวนเงิน
- EXP-2 [M] ต้นทุนต่อเที่ยว (costing): น้ำมัน + ค่าใช้จ่ายที่ผูกกับเที่ยว เทียบรายได้เที่ยว → กำไร
- EXP-3 [S] สรุปต้นทุนต่อหน่วยผลิต (ต่อถัง/ต่อแพ็ก) จาก lot ผลิต + บรรจุภัณฑ์ FIFO

### 3.14 พอร์ทัลลูกค้า (PORTAL)
- PORTAL-1 [M] ลูกค้าล็อกอินด้วยรหัสลูกค้า + PIN (4–6 หลัก, hash แยกจากระบบหลัก)
- PORTAL-2 [M] ล็อก PIN ผิด 5 ครั้ง → ล็อกพอร์ทัล แจ้ง admin ปลด (เหมือน access-status/unlock เดิม)
- PORTAL-3 [M] ดูข้อมูลของตัวเองเท่านั้น: ราคาประจำ, ยอดค้างชำระ, ถังค้างส่ง, ประวัติออเดอร์ 3 เดือนล่าสุด
- PORTAL-4 [M] ส่งคำสั่งซื้อเอง (จำนวน 4 SKU) → กลายเป็นออเดอร์ status `draft` รอ staff ยืนยัน
- PORTAL-5 [S] แจ้งปัญหา/แชท (เก็บเป็น message log)

### 3.15 แดชบอร์ด & รายงาน (RPT)
- RPT-1 [M] หน้าแรก: ยอดขายวันนี้/เดือนนี้, ออเดอร์รอส่ง, ลูกค้าเตือนหนี้ 30/60/90 วัน, สต็อกต่ำกว่า min, เครื่องจักรใกล้ PM, ใบขับขี่ใกล้หมด
- RPT-2 [M] รายงานยอดขายตามช่วงวันที่/โซน/ประเภทลูกค้า (export Excel)
- RPT-3 [S] กราฟแนวโน้มยอดขาย 12 เดือน

### 3.16 สำรองข้อมูล (BKP)
- BKP-1 [M] สำรองอัตโนมัติทุกวัน (เก็บไฟล์ .db + export JSON ตามรอบ ไว้นอกโฟลเดอร์ app) เก็บ 30 ฉบับ
- BKP-2 [M] ปุ่ม "สำรอง/คืนค่า" บนหน้า admin + ดูสถานะ backup ล่าสุด
- BKP-3 [S] อัปโหลด backup ขึ้น Google Drive ด้วย service account (แทนการเรียก gdrive.exe ทุกครั้งที่ save เดิม) ทำแบบ cron วันละครั้ง

## 4. ความต้องการไม่ใช่ฟังก์ชัน (NFR)

| รหัส | ข้อกำหนด |
|---|---|
| NFR-1 Performance | API ธุรกิจ p95 < 100ms ที่ 50 req/s, หน้าเว็บโหลดครั้งแรก < 3 วินาที (บน 4G) — บังคับ: query แบบ pagination ไม่มี endpoint ที่ return ข้อมูลทั้งก้อน |
| NFR-2 Concurrency | การบันทึกพร้อมกัน 10 ราย ต้องไม่มีข้อมูลหาย (ใช้ transaction + busy_timeout) |
| NFR-3 Security | รหัสผ่าน hash ด้วย bcrypt/argon2, JWT มี expiry, rate limit login 10 ครั้ง/นาที/IP, secret อยู่ใน .env เท่านั้น, ไฟล์ข้อมูล/backup อยู่นอก git |
| NFR-4 Auditability | แก้/ลบข้อมูลสำคัญทุกครั้งมี audit log และ stock movement ที่สืบย้อนได้ |
| NFR-5 Portability | รันได้ทั้ง local Windows (double-click script) และ Docker/Render |
| NFR-6 Data growth | รองรับ 10k orders/เดือน ≥ 5 ปีโดยไม่ต้องปรับสถาปัตยกรรม |
| NFR-7 Testability | ฟังก์ชันคำนวณ (ราคา/หนี้/สต็อก/ค่าเสื่อม) มี unit test ≥ 80% coverage; ทุก API มี integration test |
| NFR-8 UI | ภาษาไทยหลัก, รองรับมือถือ (driver + customer portal), ธีมอ่านง่าย |
