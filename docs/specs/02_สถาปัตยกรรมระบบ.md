| app.js เดียว 366KB | Vite code-split ตาม route/module |

## 2. Tech Stack (รายละเอียด + เหตุผล)

| ชั้น | เทคโนโลยี | เหตุผล |
|---|---|---|
| Runtime | Node.js ≥ 20 LTS | ตรงกับทีม/โค้ดเดิม |
| Web framework | Express 4 | คุ้นเคย, middleware ครบ |
| Database | SQLite ผ่าน `better-sqlite3` | ไฟล์เดียว สำรองง่าย, synchronous transaction ทำ code อ่านง่ายและปลอดภัยกว่า async race, รองรับ 10k order/เดือน สบาย |
| Validation | Zod | validate input ทุก endpoint + แปลง type |
| Auth | JWT (`jsonwebtoken`) + bcrypt (`bcryptjs` หรือ `argon2`) | access 15 นาที + refresh 7 วัน (เก็บใน httpOnly cookie) |

| Frontend | React 18 + Vite + TypeScript | โครงสร้างแยก module, code-split อัตโนมัติ |
| Data fetching | TanStack Query v5 | cache + invalidate ตาม query key แทน fetch-all ใหม่ |
| CSS | Tailwind CSS | เร็ว, สม่ำเสมอ |
| แผนที่ | Leaflet + OpenStreetMap | ฟรี เหมือนเดิม |
| ตาราง/ฟอร์ม | TanStack Table + React Hook Form | pagination/sort ที่ฝั่ง server |
| Export Excel | `exceljs` | สร้าง xlsx ฝั่ง server (แทน xlsx ที่ client) |
| Test | Vitest + Supertest (API), React Testing Library (UI) | วิ่งเร็ว, ใช้ได้ทั้ง unit/integration |
| Jobs | `node-cron` | backup รายวัน, alert PM/ใบขับขี่ |
| Deploy | Docker multi-stage (build frontend → serve จาก Express) + render.yaml | ทั้ง local และคลาวด์ |

## 4. รูปแบบการเขียนโค้ด (Coding Conventions) — บังคับ

1. **ภาษา:** โค้ด/ชื่อ/commit = อังกฤษ; ข้อความแสดงต่อผู้ใช้ = ไทย (ใส่ไว้ใน `messages` ของ Zod ได้)
2. **Layered:** Router (HTTP) → Service (business logic + transaction) → Repository (SQL) — **ห้าม** route เรียก SQL ตรง, ห้าม repo มี business logic
3. **Money:** เก็บเป็น integer **สตางค์** (satang) ใน SQLite เพื่อกัน floating point; แปลงตอนแสดงผลด้วย `utils/money.js` เท่านั้น
4. **วันที่:** เก็บ ISO 8601 UTC string; แสดงเป็นเวลาท้องถิ่น Asia/Bangkok
5. **ID:** มนุษย์อ่านได้ตามรูปแบบเดิม (`CUS-xxx`, `ORD-xxx`, `LOT-...`) + ใช้ `id INTEGER PRIMARY KEY` เป็น key จริง
6. **Transaction:** ทุก write ที่แตะ > 1 ตาราง ต้อง `db.transaction()(() => {...})()`
7. **Timestamps:** ทุกตารางมี `created_at`, `updated_at` (DEFAULT CURRENT_TIMESTAMP)
8. **Soft delete:** ตาราง master (customers, employees, assets, machines) ใช้ `is_active` แทน DELETE จริง
9. **Error:** โยน `AppError(status, code, messageTh)` — handler กลางแปลงเป็น JSON ตามรูปแบบในไฟล์ 04
10. **Log:** ไม่ log password/token/PIN; ใช้ `pino` level `info/warn/error`
11. **Naming:** ไฟล์ `kebab-case`, ตัวแปร/ฟังก์ชัน `camelCase`, ตาราง/คอลัมน์ `snake_case`, route `/api/kebab-case`
12. **Branch + commit:** branch ต่อ phase `feature/phase-<n>-<ชื่อ>`, commit conventional commits (`feat:`, `fix:`, `test:`, `refactor:`)

## 5. การออกแบบด้านความปลอดภัย

- **รหัสผ่าน:** bcrypt cost 10 (หรือ argon2id); ห้ามมี `passwordPlain` ในระบบและใน DB
- **Token:** access JWT 15 นาที (ส่งใน header) + refresh 7 วัน (httpOnly cookie, หมุนใหม่ทุกครั้งที่ใช้)
- **RBAC:** middleware `requireRole(...)` ทุก route; ฝั่ง frontend ซ่อนเมนูตาม role แต่**เช็คจริงที่ server เสมอ**
- **Rate limit:** `/api/auth/login` 10 req/min/IP; ทั่วไป 300 req/min
- **ล็อกบัญชี:** นับใน `users.failed_attempts`, `lock_until` (ADMIN-4 ปลดล็อกได้)
- **Secret:** `JWT_SECRET`, `PORT`, `DATA_DIR` ใน `.env` — `.env` อยู่ใน `.gitignore`; เตรียม `.env.example`
- **SQL injection:** ใช้ prepared statement ของ better-sqlite3 ทุกครั้ง — **ห้าม** string concat SQL
- **XSS:** React escape อัตโนมัติ; ห้ามใช้ `dangerouslySetInnerHTML` กับข้อมูลผู้ใช้
- **Portal isolation:** token ของ customer มี claim `scope: 'portal'` — middleware portal แยกจาก backend staff โดยสิ้นเชิง ใช้ route prefix `/api/portal/*`
- **Audit:** middleware บันทึก (user, action, entity, entityId, ip, status) ทุก request ที่ไม่ใช่ GET ที่สำเร็จ

## 6. แบบแผนการทำงานร่วมกัน (สำหรับ Freebuff/Antigravity)

- ก่อนเริ่มแต่ละ Phase: อ่าน `00_README`, `01_SRS` โมดูลที่เกี่ยวข้อง, `03_DB_Schema`, `04_API_Spec` ส่วนนั้น
- หลังเขียนเสร็จแต่ละ Phase: รัน `npm test` ให้ผ่าน 100% + เขียน README สั้นของโมดูล
- ห้ามแก้ `data/` หรือเพิ่ม dependency ใหม่นอกที่ระบุในไฟล์นี้ โดยไม่แจ้ง (ต้องถามก่อน)
- Migration ทุกครั้งเป็นไฟล์ใหม่ใน `server/src/db/migrations/` — ห้ามแก้ migration เก่าที่รันแล้ว

## 7. Performance budget (Antigravity ใช้ตรวจ)

| เป้า | ค่า |
|---|---|
| API p95 (local) | < 100ms ที่ 50 req/s (ชี้วัดด้วย autocannon ที่ endpoint หลัก 5 ตัว) |
| ขนาด JS initial ต่อ route | < 200KB gzip |
| Query ต่อ request | ≤ 5 ประโยค (เช็คจาก dev log) — กัน N+1 |
| Index | ทุกคอลัมน์ที่ใช้ WHERE/ORDER BY ใน spec ต้องมี index ตามไฟล์ 03 |
